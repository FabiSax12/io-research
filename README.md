# Operations Research project (TEC, II Semester 2026)

Internal repository for a six-person, chained assignment. The only deliverable is a **PowerPoint
presentation**; this repo exists to solve the models and to generate the material that goes on the slides
(code fragments, solution tables, network diagram, Excel file for Solver).

| Part | Content | Tools |
|------|---------|-------|
| I  | One problem each of: linear programming (LP), integer LP (ILP), transportation, assignment (LP version) | Python (PuLP, SciPy) and R (lpSolve) |
| II | One transshipment problem: matrix model, balanced and unbalanced case | Python, R and Excel Solver |

**Design principle:** every problem is a YAML file in `datos/`. The scripts read that file, so changing a
problem never requires touching code. Each script is short and self-contained (one per problem type and
language, Spanish comments, no classes) because fragments of it will be pasted onto slides.

## Repository layout

```
datos/            pl.yaml, ple.yaml, transporte.yaml, asignacion.yaml,
                  transbordo.yaml, transbordo_desbalanceado.yaml
parte1/python/    pl.py, ple.py, transporte.py, asignacion.py

resultados/       one JSON per run: <problem>_python.json / <problem>_r.json
capturas/         PNG tables, network diagram, matrix CSV/PNG, console output (.txt)
minutas/          plantilla.md (meeting minutes template)
tests/            pytest suite

```

`resultados/` and `capturas/` are regenerated by `run_all.py`, so their contents are git-ignored
(only the folders are tracked). If you want to version your final captures, remove those lines from `.gitignore`.

## Installation

Requirements: Python 3.10+ (tested on 3.14) and R 4.2+ (4.2 or newer matters on Windows: it reads UTF-8 by default).

### Python

```bash
python -m venv venv
source venv/bin/activate          # Windows (PowerShell): venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

`requirements.txt` pins `pulp>=3.0,<4`. PuLP 4.x is a rewrite with a different API (`lowBound`,
`PULP_CBC_CMD` and the other names used in every tutorial no longer work), so stay on 3.x.

### R

Install R from <https://cran.r-project.org>, then install the packages once:

```bash
Rscript instalar_paquetes.R       # installs lpSolve, yaml, jsonlite
```

`run_all.py` looks for `Rscript` in the `PATH`; if it is not there it tries the usual Windows
(`C:\Program Files\R\R-x.y.z\bin`), macOS and Linux locations, and prints a clear message when it finds nothing.

## Running

```bash
python run_all.py                  # everything: Python + R for the 6 problems, then a comparison table
python run_all.py transporte       # just one
python run_all.py pl ple           # or several
```

Valid names: `pl`, `ple`, `transporte`, `asignacion`, `transbordo`, `transbordo_desbalanceado`.

You can also run a single script from the repository root:

```bash
python parte1/python/pl.py
Rscript parte1/r/pl.R
python parte2/python/transbordo.py transbordo_desbalanceado    # optional argument: YAML name
Rscript parte2/r/transbordo.R transbordo_desbalanceado
```

Every script, in either language:

1. prints the optimal value and the solution (non-zero variables) to the console,
2. writes `resultados/<problem>_<python|r>.json` with the **same schema** in both languages,
3. writes the solution table as PNG in `capturas/<problem>_<python|r>_tabla.png`.

`run_all.py` also saves each console output to `capturas/<problem>_<python|r>.txt`, warns while a YAML still
contains the `# EJEMPLO` marker, and ends with a table (problem, Python optimum, R optimum, whether they match
within 1e-6, and the internal cross-check of each language). The exit code is non-zero if anything fails or disagrees.

### JSON schema (identical in Python and R)

```json
{
  "problema": "transporte",
  "lenguaje": "python",
  "estado": "Optimal",                  // Optimal | Infeasible | Unbounded
  "valor_objetivo": 2110.0,             // null if there is no optimum
  "variables": {"Planta A->Cliente 2": 50.0},
  "ajustes": ["Oferta (300) > demanda (270): se agregó el destino ficticio ..."],   // balancing / padding applied
  "verificacion": {"metodo": "...", "valor": 2110.0, "coincide": true}               // null when there is no cross-check
}
```

The transshipment JSON adds `"buffer": {"B": ..., "M": ...}`, and its `verificacion` is the buffer-model result.

## YAML formats

Every file starts with `# EJEMPLO - reemplazar por el problema del grupo`. **Delete that line when you load
your real data**; `run_all.py` warns until you do. The files in `datos/` are already commented; the formats are:

**Rules that apply to all files**

- `signo` must always be quoted: `"<="`, `">="`, `"="`. An unquoted `=` breaks the YAML parser.
- Quote node/agent/task/variable names that YAML 1.1 reads as booleans: `"yes"`, `"no"`, `"on"`, `"off"`, `"true"`, `"false"` (Python converts them; `y` and `n` are safe).
- Use the same name every time it appears (arcs refer to nodes by name).

### `pl.yaml` (linear programming, variables >= 0)

```yaml
nombre: Plantas de vidrio
sentido: max                 # max | min
variables: [x1, x2]
objetivo: [3, 5]             # one coefficient per variable
restricciones:               # at least 3
  - {nombre: Planta 1, coef: [1, 0], signo: "<=", rhs: 4}
  - {nombre: Planta 2, coef: [0, 2], signo: "<=", rhs: 12}
  - {nombre: Planta 3, coef: [3, 2], signo: "<=", rhs: 18}
```

### `ple.yaml` (integer LP): same as `pl.yaml` plus the integer variables

```yaml
enteras: [x1, x2]            # may be a subset; variables not listed stay continuous
```

### `transporte.yaml` (minimize cost)

```yaml
nombre: Distribución
origenes: [Planta A, Planta B, Planta C]
destinos: [Cliente 1, Cliente 2, Cliente 3, Cliente 4]
oferta: [120, 80, 100]       # one per origin
demanda: [80, 60, 70, 60]    # one per destination
costos:                      # rows = origins, columns = destinations
  - [8, 6, 10, 9]
  - [9, 12, 13, 7]
  - [14, 9, 16, 5]
```

If total supply != total demand, a `Ficticio` destination (surplus supply) or origin (surplus demand) with cost 0
is added, reported on the console and in `ajustes`.

### `asignacion.yaml` (assignment, LP version)

```yaml
nombre: Asignación de técnicos
sentido: min                 # min for costs, max for performance
agentes: [Ana, Beto, Carla, Diego]
tareas: [Trabajo 1, Trabajo 2, Trabajo 3]
matriz:                      # rows = agents, columns = tasks
  - [9, 2, 7]
  - [6, 4, 3]
  - [5, 8, 1]
  - [7, 6, 9]
```

A non-square matrix is padded with dummy rows or columns of value 0 (`Ficticio 1`, ...); whoever is assigned to a
dummy is left unassigned. The padding is reported in `ajustes`.

### `transbordo.yaml` / `transbordo_desbalanceado.yaml`

```yaml
nombre: Red con 2 plantas, 2 centros y 3 clientes
nodos:
  - {nombre: P1, tipo: origen, oferta: 60}        # origen -> oferta
  - {nombre: T1, tipo: transbordo}                # transbordo -> no quantity
  - {nombre: D1, tipo: destino, demanda: 30}      # destino -> demanda
arcos:                                            # only arcs that exist; everything else becomes M
  - {desde: P1, hasta: T1, costo: 4}
  - {desde: T1, hasta: D1, costo: 3}
```

For a different file, copy it to `datos/<name>.yaml` and run `python parte2/python/transbordo.py <name>`
(and `Rscript parte2/r/transbordo.R <name>`); to include it in `run_all.py`, add it to `PROBLEMAS`.

## How the transshipment problem is solved

Both models must give the same optimum (checked in every run):

1. **Network model**: one variable per arc, minimize total cost, and for every node
   `outflow - inflow = supply - demand` (flow conservation). PuLP in Python, `lpSolve::lp` in R.
2. **Transportation model with buffer**: every node becomes both a row and a column of an n x n matrix.
   With `B` = total flow (the larger of total supply and total demand after balancing):
   row supply = `oferta + B`, column demand = `demanda + B`, cost 0 on the diagonal (unused buffer) and `M` on arcs
   that do not exist. `M` is the power of 10 above `B * (n - 1) * max(cost)`, so no plan with an `M` arc can win.
   The matrix is solved with the transportation approach (PuLP / `lpSolve::lp.transport`).

**Unbalanced case (supply != demand):** a `Ficticio` destination (surplus supply) or origin (surplus demand) is
added with cost-0 arcs from every origin (or to every destination). The adjustment is printed and stored in
`ajustes`. Try it with `transbordo_desbalanceado.yaml`.

Outputs: `capturas/<name>_matriz_<python|r>.csv/.png` (augmented matrix for the slide),
`capturas/<name>_red.png` (network diagram, Python only) and `parte2/solver/<name>.xlsx` (Python only).

### Excel Solver (manual step)

`python parte2/python/transbordo.py` generates `parte2/solver/transbordo.xlsx` with the augmented cost matrix,
the decision cells, the `SUMPRODUCT` total cost formula, row and column sums next to supply and demand, and an
**Instrucciones** sheet with the exact Solver parameters (objective cell, variable cells, each constraint, Simplex LP,
non-negativity). Solver itself is not automated: open the file, follow the sheet, press Solve, and compare with the
expected optimum written in the same sheet. Save the solved file under another name (for example
`transbordo_resuelto.xlsx`); running the script again regenerates `transbordo.xlsx` and overwrites it.

## Tests

```bash
python -m pytest -q
```

The tests run the real scripts on temporary data (through the `IO_DIR` environment variable, so `datos/` and
`resultados/` are untouched). Expected values are either checked by hand (a 2x2 transportation problem, trivial LPs,
a small transshipment) or come from comparing both languages and both solvers. They cover automatic balancing and
padding of non-square assignments. R tests are skipped automatically if `Rscript` is not found.
